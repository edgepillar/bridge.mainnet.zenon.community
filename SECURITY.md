# Security reporting

Never put a seed phrase, private key, token, browser export, personal detail or
a working exploit in a public issue or pull request. Use public fixture
accounts for ordinary bug reports, and never send real funds to reproduce one.

For a vulnerability, use **Security > Report a vulnerability** on the
repository if GitHub shows it. If it does not, keep the details private until a
maintainer publishes a confidential channel. No contact is implied by an
account name, and none has been designated yet.

A good private report names the affected commit or build, what an attacker
needs, the impact, a minimal reproduction on disposable fixtures, and a fix if
you have one.

What the page supports, and what it has not been qualified for, is in
[SUPPORT](docs/SUPPORT.md). Security ownership, supported versions and
disclosure are for the maintainers to accept under the
[acceptance protocol](docs/ACCEPTANCE.md); CI passing does not.
